# AgentSync 構想

## 1. 概要・目的
AgentSync は、Claude と GPT が同居する **LINE 風のグループチャット**。個人がローカルで使うツールで、外部には公開しない。

- 1 つの画面で Claude と GPT の両方と会話できる
- 個別に話しかける・両方へ同時に送る・AI 同士で対話させ続ける、の 3 つの使い方ができる
- 見た目は Claude.ai 風の自作 Web アプリ
- 契約中の **Claude Pro / ChatGPT のプランの使用枠をそのまま使う**（API キーは使わない）

## 2. 機能要件
| # | 機能 | 内容 |
|---|---|---|
| F1 | 個別送信 | 宛先 `Claude` か `GPT` を選んで送る |
| F2 | 同時送信 | 宛先 `全員` → 2 体へ並列に送り、それぞれの返信を到着順に表示する |
| F3 | 対話モード | 普段のチャット画面で「対話モード」ボタンを押すと、その時点の会話の続きから Claude と GPT が交互に発言し続ける。専用の画面はなく、同じタイムラインに流れる。回数の制限はなく、止めるまで続く |
| F4 | 停止・割り込み | 対話モードは、開始したのと同じ「対話モード」ボタンをもう一度押すと止まる（実行中の CLI プロセスを kill）。対話中に自分が発言すると、それを次の話者に渡して続ける |
| F5 | 会話の管理 | 左サイドバーで会話を一覧・新規作成（⌘N）・切り替え・削除する。一覧は新しい順で、「今日」「昨日」「過去 7 日間」「それ以前」に分ける。会話の名前は最初のメッセージから自動で付け、サイドバーの「…」メニュー（右クリックでも開く）・会話のダブルクリック・ヘッダーの名前のクリックで変えられる。履歴は会話ごとに小さな JSON ファイルで残す（5 章） |
| F6 | 表示 | Markdown とコードブロックを表示する。ストリーミング表示と、各 AI がいま何をしているか（考え中・ウェブを検索中・作業中・入力中）と経過秒数を吹き出しに出す |
| F7 | モデルと考える深さの切り替え | ヘッダーにある各 AI のチップを押すと、メニューが開いて切り替えられる（Claude.ai のモデル選択と同じ感覚）。モデルは各 CLI で選べるものを**すべて**出し（アプリ側で絞り込まない）、Claude は一覧にない ID も入力できる。考える深さ（effort）は、そのモデルが受け付ける段階から選ぶ。どちらにも「自動」（CLI の設定のまま）がある。会話ごとに保存し、新しい会話にも引き継ぐ。一覧の取り方は 4 章。設定画面は持たない |
| F8 | コーディングモード | 会話にプロジェクトのフォルダを紐づけると、各 AI が普段の Claude Code / Codex と同じようにファイルを読み書きし、コマンドを実行する（詳細は 7 章） |
| F9 | 承認 | 承認の方式を会話ごとに切り替える。**承認制**（既定）: ファイル編集・コマンド実行の前に承認カードを出す（[許可] [今回は全部許可] [拒否]）。**auto**: 各 CLI の auto モードで実行し、承認カードを出さない |
| F10 | 実装＋レビュー | 実装役が編集 → レビュー役が diff をレビュー → 指摘があれば実装役が修正、を繰り返す。役割は入れ替えられる。往復回数に上限を設ける |
| F11 | ツール実行ログ | 「ファイルを読んだ」「コマンドを実行した」などの操作を、吹き出しの中に小さな行で時系列に表示する（折りたたみ可） |

- 見た目は Claude.ai に寄せる: 生成り色の背景、セリフ体の見出し、落ち着いた配色。ダークモードにも対応する

- モデルの切り替え（F7）は、ヘッダーの AI のチップから開くメニューで行う。専用の設定画面は作らない

## 4. アーキテクチャ
**Mac のデスクトップアプリ（Electron）として固める。** Dock やアプリケーションフォルダから起動し、サーバーを別に立ち上げる必要はない。

```
AgentSync.app (Electron)
├─ Renderer (React + Vite)        … 画面。Claude.ai 風のチャット UI
│      ⇅ IPC
└─ Main process (Node + TypeScript)
     ├─ Orchestrator (宛先振り分け / 対話ループ / 停止)
     ├─ ClaudeAdapter → `claude -p` (Claude Code CLI, Pro ログイン)
     ├─ CodexAdapter  → `codex app-server` (Codex CLI, ChatGPT ログイン。常駐させる)
     └─ 会話ファイル (会話ごとの JSON: 発言の並び・各AIのセッションID)
```
- **Electron を選ぶ理由**: CLI の起動・停止に Node が要るため。Electron なら Node が最初から入っているので、アプリ 1 つで完結する。画面と裏側の処理は IPC でつなぐので、ネットワークのポートを開けずに済む
- **配布**: `npm run install:app` で、`electron-builder` が `AgentSync.app` を作り、アプリケーションフォルダに入れる。個人用なので、Apple の開発者証明書での署名と公証はしない（ad-hoc 署名だけ）。自分の Mac でビルドしたアプリには「インターネットから入手した」印が付かないので、そのまま起動できる
  - Electron の使わない機能は Electron Fuses で止める（`ELECTRON_RUN_AS_NODE`・`NODE_OPTIONS`・`--inspect` を無効にし、asar の改ざんを検出する）。アプリが別の用途に使われないようにするため
- **開発中**: `npm run dev` で、ホットリロード付きで起動する
- **CLI の場所**: Finder から起動したアプリには、シェルの PATH が引き継がれない → 起動時にログインシェルから PATH を読み込む。見つからないときは、チャットにエラーと対処方法を出し、アプリのメニューの「AgentSync > CLI の場所…」でパスを指定できるようにする（設定はこれだけ）
- **モデルの一覧**: アプリに書き込まず、モデルのメニューを初めて開いたときに各 CLI から取得する（アプリを起動している間は覚えておく）。CLI が新しいモデルに対応すれば、アプリを直さなくても選べるようになる
  - GPT: app-server の `model/list` をそのまま全部出す（`hidden` のものは除く）。「自動」は `config/read` の `model`、なければ `isDefault` のモデル
  - Claude: Claude Code を `--input-format stream-json` で起動し、`initialize` の制御リクエストを送ると、/model のメニューと同じ一覧（`value`・表示名・説明・選べる effort）が返る。プロンプトは送らないので使用枠は使わない（約 1 秒）。返事にはアカウントの情報も入っているが、`models` 以外は読まない。`default`（Claude Code が自分で選ぶモデル）は「自動」として扱う。一覧にないモデル ID も入力できる
  - 推論の強さ（effort）は、そのモデルが受け付ける段階を出す（Claude は `supportedEffortLevels`、GPT は `supportedReasoningEfforts`）。モデルを替えたときに今の effort を受け付けないなら、「自動」に戻す
  - 選んだモデル（`model`）と、CLI が実際に使ったと答えたモデル（`activeModel`）は分けて持つ。会話のファイルには選んだほうを残す。ヘッダーには、使ったモデルが分かればそれを、まだならば選んだものを表示する
- **データの保存先**: `~/Library/Application Support/AgentSync/`（会話ごとの JSON ファイルと、チャット用の空の作業ディレクトリ）。開発中（`npm run dev`）は `AgentSync-dev/` を使い、普段使いのデータと混ぜない。同じデータのアプリは 1 つしか起動しない
- **Adapter の共通インターフェース**: `send(convId, text, onDelta) → {text, sessionId}` と `abort()`。将来 API キー方式（Anthropic / OpenAI API）や Gemini などを足すときも、Adapter を追加するだけで済むようにする
- **Claude**: `claude -p --output-format stream-json --resume <sessionId> --model … --append-system-prompt …` で呼ぶ。ツールは無効にし、空の作業ディレクトリで実行する（チャット専用にする）
- **GPT**: `codex app-server` を 1 つ常駐させ、JSON-RPC で話す。会話ごとに `thread/start`（2 回目以降は `thread/resume`）、発言ごとに `turn/start`。返答は `item/agentMessage/delta` で 1 文字ずつ届き、停止は `turn/interrupt`。チャットでは `sandbox: read-only`・`approvalPolicy: never` で、作業ディレクトリは空にする。当初は `codex exec` を予定していたが、少しずつ届く表示・途中停止・承認の中継がすべて app-server でできるので、チャットとコーディングの両方を app-server に統一した
- **グループ文脈の渡し方（差分方式）**: 各 AI は自分の CLI セッションを持ち続ける。送るときは「その AI が前回発言してから後に増えた、他の参加者の発言」を `[ユーザー]: … / [GPT]: …` の形でまとめて渡す。会話全体を毎回送らないので、使用枠を節約できる
- **system プロンプトの方針**: 「あなたは Claude。グループチャットにユーザーと GPT がいる。発言者のラベルを付けずに、自分の発言だけを返す」

## 5. 会話の保存（JSON ファイル）
- **前提**: CLI 経由の会話はクラウドに保存されない。各 CLI が Mac の中に自分側のやり取りだけを残す（Claude Code は `~/.claude/projects/`、Codex は `~/.codex/sessions/`）。グループチャットの並び（誰が誰に何を言ったか）はどちらにも残らない
- **方針**: DB は持たない。会話ごとに JSON ファイルを 1 つだけ残す。中身は発言の並びと、各 CLI のセッション ID。アプリを閉じても、続きから再開できる
- **保存先**: `~/Library/Application Support/AgentSync/conversations/<id>.json`
- **中身の例**:
```json
{
  "version": 1,
  "id": "mwjy4kz9-dc1a4d",
  "title": "設計相談",
  "kind": "chat",
  "workdir": null,
  "createdAt": "2026-11-17T00:20:22.965Z",
  "updatedAt": "2026-11-17T00:21:40.112Z",
  "participants": {
    "claude": { "model": "claude-opus-5-5", "sessionId": "…", "delivered": [1, 3] },
    "gpt":    { "model": "gpt-6-sol",       "sessionId": "…", "delivered": [1] }
  },
  "messages": [
    { "id": 1, "from": "user",   "to": "all",  "text": "DB は何がいい？", "at": "2026-11-17T00:20:22.965Z", "status": "done" },
    { "id": 2, "from": "claude", "to": "user", "text": "SQLite で十分です…", "at": "2026-11-17T00:20:23.368Z", "status": "done" }
  ]
}
```
- `kind` はチャット会話なら `chat`、コーディング会話なら `coding`。`workdir` はコーディング会話のときだけプロジェクトのフォルダが入る
- `delivered` は、その AI の CLI セッションにもう渡した発言の ID。返信が流れている途中の発言はその場では渡さず、あとで渡すので、「どこまで読んだか」の番号 1 つではなく ID の集まりで持つ
- 書き込みは、一時ファイルに書いてから置き換える（途中で落ちても壊れない）。ファイルは自分だけが読める権限（600）にする。変更のたびではなく、少し待ってまとめて書く（返信が少しずつ届く間は書かない）
- 返信の途中でアプリを終了したときは、そこまでの文章を残し、次に開いたときは「停止しました」として表示する
- 新しい会話は、最初のメッセージを送るまでファイルを作らない。読めないファイルや新しい形式のファイルは、一覧から外すだけで消さない
- ツール実行ログは、発言の `tools` に要約だけを入れる（`{ kind: read|edit|bash|search, summary, approval }`）。詳しい中身は各 CLI 側の記録にある

## 6. 対話モードの仕様
1. **開始**: チャット画面の「対話モード」ボタンを押すと、その時点の会話から始まる。専用の画面や開始用のフォームはない
2. **最初の話者**: 最後に発言した AI ではない方から始める。最後の発言がユーザーなら Claude から始める。変えたいときは、チャットで「GPT から話して」のように指示する
   - 対話モード専用の設定画面は持たない。ボタンを押して始め、もう一度押して止めるだけ
3. **進行**: 話者 A に差分を送る → 返信を表示 → 話者 B に差分を送る → … を交互に繰り返す
4. **回数の制限はない**。終了するのは「対話モード」ボタンをもう一度押したとき、または CLI がエラーを返したとき（使用枠の上限なども含む）だけ
5. **割り込み**: ユーザーの発言はキューに入れて次の話者への差分に含める。ループは止めずに続ける
6. 停止したあとは普段のチャットに戻る。もう一度ボタンを押せば、続きから再開できる

実装で決めたこと（2026-11-17）:
- 「ここから対話モード · Claude から開始」「対話モードを止めました」は、AgentSync 自身の発言（`from: system`、`notice` 付き）としてタイムラインに入れ、会話のファイルにも残す。各 AI には「【AgentSync からのお知らせ】」として、相手の名前を入れた言い方（「あなたと GPT が交互に発言し…」）で届く。止めたお知らせも届くので、普段のチャットに戻ったことが AI にも分かる
- 対話中の返事は、相手の AI 宛て（「▸ GPT への返信」）にする。各 AI には、相手の最新の発言が「【GPT → あなた】」として届く
- 最初の話者: 最後に話した AI ではない方。最後の発言があなたのものなら Claude（GPT 宛てだったら GPT）。ボタンを押した時点で返事の途中の AI がいれば、それが終わるのを待ってから始める
- 割り込み: 対話中に送った発言では、AI を新しく呼ばない。次の話者への差分に入り、タイムラインでは「割り込み · 次の話者に渡されます」と表示する
- 止まるとき: もう一度押したとき・「停止」を押したとき（話している途中の返事も止める）、返事がエラーになったとき、次の話者に渡す発言がないとき。アプリを対話中に終了した会話は、次に開いたときに止めたお知らせを足す
- 画面: 入力欄の上の「対話モード」ボタン（ON の間はオレンジ）、その上に「対話モード中 · N 発言 · 次: GPT」の帯、サイドバーの会話に対話中の印。話題がない（まだ何も話していない）会話では押せない

## 7. コーディングモード
基本は「普段の Claude Code / Codex をそのまま使う」こと。その上に、2 体ならではの使い方として「設計の対話」と「実装＋レビュー」を足す。

### 7.1 会話の種類
| 種類 | 作業フォルダ | ツール |
|---|---|---|
| チャット会話 | 空の作業ディレクトリ | 無効 |
| コーディング会話 | ユーザーが選んだプロジェクトのフォルダ（git リポジトリ推奨） | 有効（承認制） |

- コーディング会話を新規作成するときにフォルダを選ぶ。ヘッダーにフォルダ名とブランチ名を表示する

### 7.2 使い方
1. **単独で使う**: 宛先を `Claude` か `GPT` にして話しかける。普段の Claude Code / Codex と同じように動く（ファイルの読み書き、コマンド実行）
2. **設計の対話**: 対話モード（6 章）をコーディング会話で使う。両者とも**読み取り専用**でコードを読みながら設計を議論する。終わったら、結論を実装役にそのまま渡せる
3. **実装＋レビュー**: 下のループを回す

### 7.3 実装＋レビューのループ
1. ユーザーがタスクを出し、実装役（既定 Claude）とレビュー役（既定 GPT）を選ぶ
2. 実装役が編集・テストを行う（承認制）
3. 実装役のターンが終わったら、アプリが `git diff` を取り、タスク文と一緒にレビュー役へ渡す。レビュー役は**読み取り専用**
4. レビュー役は指摘を返す。問題がなければ、決められた合図（`APPROVED`）を返す
5. 指摘があれば、それを実装役に渡して 2 に戻る
6. 終了条件: `APPROVED` が出たとき／往復回数の上限（既定 3）に達したとき／「実装＋レビュー」ボタンをもう一度押したとき
7. ユーザーは途中で割り込める（指摘の取捨選択など）

### 7.4 安全のルール
- **書き込みは常に 1 体だけ**: 書き込み権限を持つのはその時点の担当 1 体だけにする。`全員` 宛てにした場合、2 体とも読み取り専用で答える
- **承認の方式**（入力欄のトグルで、会話ごと・途中でも切り替えられる）
  - **承認制**（既定）: ファイルの編集とコマンドの実行は、毎回承認カードで確認する。ファイルの読み取りと検索は自動で許可する
  - **auto**: 各 CLI の auto モードに任せる。承認カードは出さず、ツール実行ログだけを流す。CLI 側が「危険」と判断して止めた操作は、承認カードとして表示する
  - 実装＋レビューのループ中も同じ方式に従う。auto にすると、ループが止まらずに最後まで回る
- auto モードでも、レビュー役と「全員」宛ての回答は読み取り専用のままにする（書き込むのは常に 1 体だけ）
- **作業フォルダの外には書き込ませない**
- 実装＋レビューを始めるときは、作業ブランチを作るよう提案する（変更をまとめて捨てられるように）

### 7.5 CLI との繋ぎ方
| | Claude | GPT |
|---|---|---|
| 呼び出し | `claude -p --output-format stream-json`（作業ディレクトリ = プロジェクトのフォルダ） | `codex app-server`（JSON-RPC で常駐させる） |
| 承認 | `--permission-prompt-tool` に、アプリが立てる MCP ツールを指定 → 承認カードに中継する | app-server からの承認リクエスト（コマンド実行・パッチ適用）を承認カードに中継する |
| auto | `--permission-mode auto`（Claude Code の auto モード） | `--sandbox workspace-write` で、承認ポリシーは auto 相当（`--full-auto` 相当） |
| 読み取り専用 | `--permission-mode plan` か、許可するツールを読み取り系に絞る | `--sandbox read-only` |
| ログ | stream-json の tool_use / tool_result イベント | app-server のイベント通知 |

- Adapter のインターフェースに `mode: chat | read-only | write` と `onToolEvent` / `onApprovalRequest` を追加する

### 7.6 実装で決めたこと（2026-11-17）
- 各ターンの権限（`access`）: チャット会話は `chat`（ツールなし）。コーディング会話では、宛先にした AI だけが `write`、「全員」宛て・対話モード・レビュー役は `read`。ほかの AI が `write` で作業している間に頼まれた AI は `read` になる（書き込むのは常に 1 体だけ）
- Claude: `read` は `--tools Read,Glob,Grep --permission-prompts none`。`write` は `--input-format stream-json --permission-mode manual|auto --permission-prompts host --permission-prompt-tool stdio`。許可が必要な操作の前に `control_request`（`can_use_tool`、ツール名と入力付き）が届き、`control_response` の `behavior: allow|deny` で答える。システムプロンプトは `--append-system-prompt`（Claude Code の普段の指示の上にグループの説明を足す）。作業フォルダの外へのファイル編集（Write・Edit など）は、聞かずに断る
- Codex: `read` は `sandbox: read-only`・`approvalPolicy: never`。`write` は `workspace-write` と、承認制なら `untrusted`、auto なら `on-request`。同じスレッドで読み取りと書き込みが入れ替わるので、`turn/start` ごとに `approvalPolicy` と `sandboxPolicy` を渡す。承認は app-server からのリクエスト（`item/commandExecution/requestApproval`・`item/fileChange/requestApproval`）に `accept|decline` で答える。コマンドの `commandActions` が読み取り・一覧・検索だけなら、聞かずに許可する（`untrusted` では `cat` や `sed -n` も聞いてくるため）。ファイル変更の差分は、同じ ID の `fileChange` 項目から取って承認カードに出す
- 承認カード: 「許可」「今回は全部許可」（その返事の残りも許可）「拒否」。返事が終わる・止まると、答えていないカードは「拒否」として閉じる。答えを待つ間、その AI の状態は「あなたの承認待ち」
- 作業ログ: Claude は `tool_use`／`tool_result`、Codex は `item/started`／`item/completed`（コマンドは `/bin/zsh -lc "…"` を外して表示）。返事ごとに会話のファイルにも残す
- 実装＋レビュー: 入力欄の依頼（空なら直前の依頼）を実装役宛ての発言として載せ、ほかの AI には返事をさせずにループを始める。実装役のターンが終わるたびに、アプリが `git diff HEAD` と新しいファイル（未追跡）の中身を読み、「変更をレビュー役に渡しました · N ファイル、+a −b」のお知らせ（差分は「差分を見る」で開ける）としてレビュー役に渡す。リポジトリには何も書き込まない。レビュー役の返事の最初の行が `APPROVED` なら終わり、上限（3 往復）でも止まる。始めるときに main／master にいれば、作業ブランチで進めるよう勧める
- ブランチ名は、会話を開いたときと、書き込みのターンが終わるたびに `git rev-parse --abbrev-ref HEAD` で読み直す

## 8. 制約・リスク
- **使用枠**: Pro の利用制限に当たると CLI がエラーを返す → そのメッセージをチャットに表示し、対話を止める
- **対話モードの止め忘れ**: 回数の制限がないので、止めないと使用枠を使い続ける → 対話中はバーを常に出し、アプリのウィンドウを閉じたら自動で止める
- **規約**: どちらの CLI も「本人が自分のマシンで使う」範囲で使う。サブスクの認証を外部に公開・共有しない（アプリはネットワークのポートを開けない）
- **速度**: CLI はプロセスの起動があるぶん API より遅い（1 発言あたり数秒の上乗せ）。まず動かしてみて、遅すぎる場合はプロセスを常駐させる方式を検討する
- CLI のオプションはバージョンによって変わる可能性がある → 11 章の確認結果を基準にし、CLI を更新したら `npm run test:e2e` で確かめる
- **コーディングモードの承認の中継**: CLI が承認リクエストを外部に出す方法（Claude の `--permission-prompt-tool`、Codex の app-server）が想定どおりに動くかが一番のリスク → Phase 5 で、どちらも実際に中継できることを確かめた（11 章）
- **auto モード**: 確認なしで編集・実行するので、誤操作に気づきにくい → 作業ブランチで使うよう促す。auto の間はヘッダーに目立つバッジを出す
- **使用枠の消費**: 実装＋レビューのループは使用枠を多く使う → 往復回数の上限を低めにする（既定 3）

## 11. 実機での確認結果（2026-11-16）
確認した環境: Claude Code 2.1.308、Codex CLI 0.169.0（どちらもサブスクのアカウントでログイン済み）

| 項目 | Claude（`claude -p`） | GPT（`codex app-server`） |
|---|---|---|

| auto モード | `--permission-mode auto` がある | `approvalPolicy` と `sandbox: workspace-write` |
| 承認の中継 | `--permission-prompts host` と `--permission-prompt-tool` がある | `item/commandExecution/requestApproval` などのサーバーからのリクエスト |

| モデル一覧 | 一覧を出すコマンドはない（`--model` に別名か正式 ID を渡す） | `model/list`（`codex debug models` と同じ中身） |

### Phase 2 で確かめたこと（2026-11-17）
- `.app` を Finder と同じ方法（`open`）で起動すると、PATH は最小限になる。それでも、ログインシェルから読み込んだ PATH で、両方の CLI が見つかった
- アプリを起動し直しても、保存したセッション ID で続きから話せる。Claude は `--resume`、GPT は新しい app-server のプロセスでの `thread/resume`。それぞれ、自分だけに伝えられた合言葉を覚えていた（`npm run test:e2e`）
- **GPT はチャットでもウェブ検索を使う**（「今日の東京の天気」を調べてリンク付きで答えた）。Claude はチャットではツールを無効にしているので調べられない。両方とも調べられるようにするか（Claude Code の WebSearch を許可する）は、後で決める
- CommonMark では、`築地の**「市場」**です` のように、日本語の文字と記号の間にある `**` が太字にならない → `remark-cjk-friendly` で直した
- Electron の ESM のメインスクリプトで、トップレベルの `await app.whenReady()` を書くと、ready が来ずに止まる → `.then()` でつなぐ

### 使ってみて直したこと（2026-11-17）
- 「全員」に送ると、2 人は同時に動いている。それでも順番に答えているように見えたのは、GPT が書き始めるのが遅いため。同じ質問を同時に送って測った結果:

  | | 考え始め | 書き始め | 終わり |
  |---|---|---|---|
  | Claude（claude-opus-5-5） | 2.5 秒 | 2.5 秒 | 3.8 秒 |
  | GPT（gpt-6.1-sol、考える深さ xhigh） | 0.7 秒 | 5.3 秒 | 22.6 秒（途中でウェブ検索） |

  → 吹き出しに、いま何をしているか（考え中・ウェブを検索中・作業中・入力中）と経過秒数を出すようにした。2 人ぶんが同時に数え上がる
- GPT の考える深さを `medium` や `low` に下げても、この質問では 15 秒前後かかった。時間の多くはウェブ検索で、深さを下げても大きくは縮まない
- 状態の取り方: Claude は `content_block_start` の種類（`thinking`、ツールの使用）、Codex は `item/started` の種類（`reasoning`、`webSearch` とその `query`、コマンドの実行など）。考えている内容そのものは、どちらからも空で届く（Claude の thinking は空、Codex は要約を頼んでも空）ので表示しない
- 状態の変化（`agent:activity`）はすぐに変わる一時的なものなので、保存も一覧の更新もしない
- macOS 26 では、アプリのアイコンを OS が角の丸い形に切り抜き、縁を光らせて表示する。824 × 824 の角丸のタイル（1024 × 1024 の中央）なら、灰色の枠に入れられずにそのまま表示される（`NSWorkspace` で OS が描く絵を書き出して確認した）
- 考える深さ（effort）を変えて GPT の速さを測った（同じ質問、1 回ずつなのでばらつきは大きい）。書き始めはどの設定でも 2〜8 秒で、effort ではあまり変わらない。終わりまでの時間はウェブ検索をするかどうかで大きく変わる（検索あり 11〜14 秒、なし 4〜10 秒）。low にして 2 人に送ると、Claude（3.6 秒）が書いている途中で GPT（5.1 秒）も書き始めた
- effort の渡し方: Claude は `claude -p --effort <level>`（low・medium・high・xhigh・max。init イベントは既定の段階を教えない）。Codex は `turn/start` の `effort`。Codex は turn で渡した effort をそのスレッドの次の turn にも使い続けるので、「自動」に戻すときは設定の値（`config/read` の `model_reasoning_effort`、なければ `model/list` のモデルの既定）を名前で渡す。前の実行で effort を変えたかもしれない再開スレッドも同じ
- 選べる段階はモデルによって違う（例: gpt-6.1-sol は low〜ultra、gpt-6-luna は low〜max）→ `model/list` の `supportedReasoningEfforts` をそのまま出す

### Phase 3 で確かめたこと（2026-11-17）

- CLI が見つからないときの説明は「AgentSync > CLI の場所…」を案内する。指定した場所に CLI がない場合も同じ
- Markdown では 1 回の改行が空白になり、1 行に 1 つずつ書いた返事が 1 行につながっていた → `remark-breaks` で改行のまま表示する

### Phase 5 で確かめたこと（2026-11-17）
- Claude Code は `--permission-prompts host` だけでは承認を問い合わせず、自動で断る。`--permission-prompt-tool stdio` も付けると、操作の前に `can_use_tool` の制御リクエストが届く（Agent SDK と同じ仕組み）。「許可」で実行され、「拒否」なら Claude は実行せずに理由を返した
- Codex は `untrusted` で、コマンドの前に `item/commandExecution/requestApproval`（コマンド・作業フォルダ・`commandActions` 付き）、パッチの前に `item/fileChange/requestApproval` を送る。`on-request` では作業フォルダの中の作業を聞かずに進めた
- 使い捨てのプロジェクトで、承認制のまま「Claude に関数名の変更」「GPT に処理の追加」を頼み、カードで許可するとファイルが変わった。「全員」宛てでは 2 人とも読み取り専用でカードは出ず、auto ではカードなしで Claude が README を更新し、GPT に削除を頼んでカードで拒否するとファイルは残った
- 実装＋レビュー（auto、effort low）: Claude が実装（編集と `node greet.js` で確認、約 28 秒）→ 差分をレビュー役に渡す → GPT が APPROVED を返して止まった（合計約 35 秒）。main ブランチだったので、作業ブランチを勧めるお知らせが出た
- 作業ログの「実行中」の行に、行と点の両方で同じクラス名（`work-running`）を使っていて、行が点の大きさ（幅 7px）につぶれていた → 点を `work-dot` に分けた
